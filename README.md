# 部落冲突帮手时间计算器

一款面向《部落冲突》玩家的升级时间估算工具。根据升级项目的当前剩余时间、帮手类型与等级，以及共享工作日状态，计算持续指派帮手后的预计完成时间。

在线访问：[https://time.yierbubu.store](https://time.yierbubu.store)

## 支持的帮手

| 帮手 | 支持项目 | 最高等级 | 单次效果 |
| --- | --- | ---: | --- |
| 实验助手 | 兵种、法术和攻城机器的实验室研究 | 12级 | 工作1小时，按等级额外加速1–12小时 |
| 建筑工人学徒 | 建筑、陷阱和英雄等施工项目 | 8级 | 工作1小时，按等级额外加速1–8小时 |

项目在等待和帮手工作期间都会正常推进。计算时会同时计入项目自身进度和帮手提供的额外进度。

## 工作日状态

实验助手与建筑工人学徒使用同一个23小时共享工作日计时器。工具支持四种起始状态：

- **全部已刷新，现在可用**：立即安排本轮工作，并从当前时间开始计算下一轮23小时工作日。
- **共享倒计时中，本轮尚未使用**：立即安排本轮工作，下一轮仍按当前共享倒计时结束时间开始。
- **正在工作**：先计算当前剩余工作时段，再根据本轮已经经过的时间推导下一次共享工作日边界。
- **本轮已经使用**：先等待当前共享倒计时结束，再安排下一轮工作。

工具默认按照“持续指派”计算，即每个可用工作日都继续让当前帮手加速同一个项目。如果项目在一次工作过程中完成，只计算实际使用的部分加速时间。

## 已实现功能

- 从简体中文横屏“帮手详情页”截图识别帮手、等级、实际生效等级、工作状态、倒计时和可见项目。
- 截图支持文件选择、拖放、粘贴和手机相册，接受 PNG、JPEG、WebP，单张最大20 MB。
- 识别结果先进入可编辑核对区；选择项目并确认后才会填写计算器，不会自动执行计算。
- 无法可靠读取的游戏描边数字保持为0并提示手动核对，不静默采用可疑值。
- “当前效果”与显示等级不同时，使用实际生效等级计算。
- “正在工作”的秒数向上取整到分钟，并计算本轮剩余加速和后续23小时工作日。
- 在实验助手和建筑工人学徒之间切换，并自动应用对应等级上限。
- 输入项目剩余的天、小时和分钟。
- 选择帮手等级，直接显示该等级每轮提供的加速小时数。
- 选择当前共享工作日状态，并在需要时填写剩余倒计时。
- 计算不使用帮手时的原完成时间。
- 计算持续使用帮手后的预计完成时间。
- 展示预计节省时间、预计加速次数和每轮加速时间点。
- 长加速记录默认显示前10次和最后1次，可展开或收起全部记录。
- 修改任意输入参数后自动清除旧结果，避免继续显示过期计算结果。
- 所有时间输入框默认值为0；清空后会自动恢复为0。
- 手机端时间输入优先显示数字键盘，桌面端保留数字微调控件。
- 自适应桌面和手机屏幕。
- 使用当前设备时区显示计算时间。
- 配置 SVG 标签页图标和 Supercell 非官方内容声明。

## 输入规则

- 所有时间必须填写非负整数。
- 项目剩余时间必须大于0且不能超过365天。
- 剩余时间中的小时范围为0–23，分钟范围为0–59。
- 共享倒计时必须大于0且不能超过23小时。
- 正在工作时，本轮剩余工作时间必须大于0且不能超过60分钟。
- 选择“全部已刷新，现在可用”时不需要填写共享倒计时。

## 计算结果说明

| 结果 | 含义 |
| --- | --- |
| 使用帮手后 | 持续指派当前帮手时的预计升级完成时间 |
| 原完成时间 | 不使用帮手、仅按自然进度计算的完成时间 |
| 预计节省 | 帮手带来的额外时间缩短量 |
| 预计加速 | 项目完成前预计触发的帮手工作次数 |
| 预计加速记录 | 每轮开始时间、完整或部分加速状态，以及实际加速时长 |

## 计算范围

当前计算只包含实验助手或建筑工人学徒的持续加速，不包含以下情况：

- 建筑工人药水、研究药水或其他临时加速效果；
- 使用宝书、战锤、宝石等方式立即完成项目；
- 中途更换升级项目、帮手等级或停止持续指派；
- 游戏维护、设备时间不准确或未来机制调整造成的偏差。

本工具不会连接游戏账号。手动输入、截图识别和时间计算全部在当前浏览器完成，截图不会上传，也不会写入本地存储。识别结束、更换图片或离开页面时会释放图片预览资源。

## 截图识别说明

截图识别覆盖以下六种组合：实验助手和建筑工人学徒各自的“空闲中”“正在工作”“需等待”状态。第一版仅支持完整、未旋转的简体中文横屏帮手详情页；严重裁剪、其他语言或过度压缩的图片需要改用手动填写。

识别使用 Tesseract.js Web Worker，并在第一次使用截图功能时懒加载。简体中文、英文数字模型、Worker 和 WebAssembly 文件均由本站同源提供，不依赖运行时第三方 OCR 服务。浏览器会缓存模型，因此第一次识别通常比后续识别慢。

游戏字体带有描边、渐变和图标遮挡，部分项目时间可能无法可靠识别。页面会将这些字段标为需要核对并保持0；只有补全有效时间、选择项目并勾选确认后，识别结果才能应用到计算器。

- Vue 3
- TypeScript

- Vitest

## 本地开发

项目要求 Node.js `>=24.15 <25`，仓库内的 `.nvmrc` 固定为 `24.15.0`。

使用 nvm 切换版本：

```bash
nvm install 24.15.0
nvm use 24.15.0
```

安装依赖并启动开发服务：

```bash
npm ci
npm run dev
```

浏览器访问终端中显示的本地地址，Vite 默认使用 `http://localhost:5173/`。

## 测试与构建

运行全部计算和界面测试：

```bash
npm test
```

执行 TypeScript 检查并生成生产文件：

```bash
npm run build
```

构建结果输出到 `dist/` 目录。当前测试覆盖计算边界、四种共享工作日状态、帮手等级上限、六类截图文本解析、秒数取整、实际生效等级、识别确认流程、默认值、清空归零、手机数字输入、结果失效和长记录折叠。

## GitHub Pages 部署

推送到 `main` 分支后，`.github/workflows/deploy.yml` 会自动执行：

1. 使用 Node.js 24 安装依赖；
2. 运行全部测试；
3. 执行生产构建；
4. 上传构建产物并部署到 GitHub Pages。

自定义域名由 `public/CNAME` 配置为 `time.yierbubu.store`。
